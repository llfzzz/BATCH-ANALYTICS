# 工程难点、验证与演进

## 实现大纲

1. 真实Spark读多来源完整快照，原始行与批次哈希写ODS。
2. DataFrame规范化薪资、技能别名与字段，隔离错误。
3. SQL窗口选择源内/跨源最新，保留历史和关闭语义。
4. DWS计算技能/薪资与连续日期as-of趋势，补齐0值后LAG。
5. 明确必要技能与偏好，先硬筛选，再MLlib CountVectorizer/IDF/L2 cosine。
6. 完整派生snapshot发布、指纹缓存、只读API和中文招聘工作台。

## 技术难点

**事件时间与补数。** 按snapshot_ts排序，而非批次导入时间。“有效 → 关闭 → 旧有效补数”最终仍关闭。趋势先为每个自然日取当时最新状态，再展开技能，避免把更新次数当作岗位需求。

**增量与缓存分开。** ODS批次增量是真实持久化；派生层仍全量重建。代码、画像或新增批次改变指纹，缓存不会误命中。输入文件删除不删除已提交历史。相同ID内容改变直接失败，修正必须新ID。

**原子发布与恢复。** staging中先构建报告、模型和分区数据，生成完整文件SHA清单后变为snapshot。current指针只在成功时替换，注入发布前异常的测试验证上一报告字节不变。缺模型metadata会触发重建。进程锁只支持本机单写者；多文件读者应先固定snapshot路径；当前不提供对象存储事务或ACID表格式。

**硬要求的证据边界。** 显式required_skills才是技能硬门槛。preferred_skills缺失可入选，skills未分级标签只做排序与差距展示。未知届别、位置或不一致坐标体系不会猜测放行。相似度不是招聘资格，也不是录用概率。

**计算留在Spark。** ETL、连接、窗口、聚合、模型训练和cosine都用Spark算子；只有最终有限结果导出到Python JSON。没有全量collect后做所谓“大数据匹配”。真实Parquet扫描计划保存PartitionFilters，可核对分区裁剪。

**数据口径。** 日薪/月薪/年薪/时薪统一比较口径而不丢原文；未知薪资不填0。直线距离不等于通勤距离。默认样例有66条反向毕业年份版本，与显式脏输入一起隔离，禁止静默改成可投年份。

## 0.2.0 验证

`make test`含原有薪资/距离/届别/版本/空状态测试，以及必要/偏好、缓存命中、画像变更、代码变更、模型文件删除恢复、失败发布、新批次失效和同ID变更拒绝。API验证样例标识、契约错误、证据和跨snapshot执行状态隔离。

`make verify`用真实Spark跑默认全链路并再次调用，验证cache_hit和0行派生重建，核对四层文件、模型、关闭与补数。公开摘要在evidence/validation.json；本地细节在被忽略的artifacts中。GitHub CI会在Ubuntu/Java21/Python3.12重新实际执行。

## 规模边界

当前是local[2]、数百条固定种子快照的功能验收。不能写成真实招聘数据、百万级压测、集群调优或推荐准确率提升。业务指纹可能错误合并同名岗位；TF-IDF不建模经历熟练度；as-of范围连接和全部派生重建随历史增长需要改进；snapshot保留暂未自动回收。
